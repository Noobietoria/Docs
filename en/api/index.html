    Noobietoria Studio — API Reference¶

    Accessory¶

    Items available on the Noobietoria Marketplace.

    Note: Accessory only includes Items and Clothes. Other items such as Gamepasses cannot be equipped, no matter how hard you try to enter them.

    How to set up:

    • For a player: [Player Name] -> IngameAccessoriesID, then enter the ID string
    • For an NPC: [NPC Name] -> IngameAccessoriesID, then enter the ID string

    The ID string is separated by commas (,), and no purchase is required to equip them on a player.

    They cannot be set up in the player's DefaultAccessories section, because this section contains the items the player has already equipped. You can only toggle the DefaultAccessories variable on the Player root.

    AccessoryService¶

    A mechanism similar to Accessory, but this one is a static variable and cannot be overridden with Luau.

    Note: All 3 parameters are strings and must not be nil.

    -- Equip accessories on a player named "Player1"
AccessoryService("Player1", "Player", "1082345, 1082350, 1082360")
-- Equip accessories on an NPC named "ShopKeeper" in Workspace
AccessoryService("ShopKeeper", "NPC", "12345678, 87654321")

    AudioAssets¶

    Use audio in any game.

    Note: Audio only includes sound clips (long or short, our team doesn't care). Other types of Assets are not accepted and will not work.

    How to set up:

    • Create: New -> Audio, then go to Audio -> ID and enter the ID.
    • Enable Loop: Audio -> Loop = true

    DataStoreService¶

    DataStoreService is the service that lets you store and retrieve data from our database.

    Limits:

    • Up to 15 datastores per game
    • Maximum capacity: Key up to 50 ASCII characters and value up to 1MB. Total capacity is 25MB + (5MB×N), where N is the number of visits.
    • Request limit: 15 + (10×N) requests/server/minute where N is the CCU, and 16 concurrent connections to DataStores in total across the whole server.

    Note:

    • Init establishes the connection to the datastore. You need to call Close when you are done.
    • SessionID is a random string you generate yourself — anything works as long as it's base32.
    • Value must be JSON.
    • If you don't send any message within 15 seconds, the connection is automatically closed. If there is data still being processed that hasn't been confirmed yet, it will wait until it finishes.
    DataStoreService.Init(SessionID)
DataStoreService.Close(SessionID)
DataStoreService.Insert(SessionID, Key, Value)
DataStoreService.Get(SessionID, Key)
DataStoreService.GetKeys(SessionID)
DataStoreService.Delete(SessionID, Key)

--- for lazy devs: we've included the Roblox-side APIs too. Connection is managed automatically.
DataStoreService:GetDataStore(name, scope)
DataStoreService:GetOrderedDataStore(name, scope)
DataStoreService:GetRequestBudgetForRequestType(requestType)
DataStore:GetAsync(key)
DataStore:SetAsync(key, value, userIds, options)
DataStore:UpdateAsync(key, transformFunction)
DataStore:RemoveAsync(key)

    InstanceService¶

    InstanceService is a service that lets you create, delete, get GUIDs for and move Instances (Part, Model, NetworkEvent, ServerScript, ClientScript, ModuleScript, ...) within Workspace or other containers (ReplicatedStorage, ServerStorage, StarterPlayerScripts, ...).

    Note:

    • Name is the name of the Instance (string).
    • Type is the type of Instance to create (string, e.g.: "Part", "Model", "SpawnLocation", "NetworkEvent", "ServerScript", "ClientScript", "ModuleScript").
    • Parent is the name of the parent Instance or the name of the root container ("Workspace", "ReplicatedStorage", "ServerStorage", "StarterPlayerScripts", ...).
    • GUID is the unique identifier of an Instance, used instead of the name when multiple Instances share the same name.
    • Position is a coordinate table {X, Y, Z} (only applies to Instances that have a position in 3D space, e.g. Part).
    • Index in GetGUID(Name, Index) is the ordinal number (starting from 1) of the Instance among same-named Instances, ordered by creation time. If Index is omitted, it defaults to Index = 1.
    • Use GetGUIDs(Name) to get the GUIDs of all same-named Instances at once.
    • When Type is "ServerScript" or "ClientScript", pass the Source (Luau code) via Properties.Source; Enabled defaults to true, and you can pass Properties.Enabled = false to create it without running it right away.
    • When Type is "ModuleScript", Properties.Source must contain code that returns a value, otherwise it will error when required.
    InstanceService.Create(Name, Type, Parent, Properties)
InstanceService.Destroy(Name, Index)
InstanceService.DestroyByGUID(GUID)
InstanceService.GetGUID(Name, Index)
InstanceService.GetGUIDs(Name)
InstanceService.GetByGUID(GUID)
InstanceService.Move(Name, Position, Index)
InstanceService.MoveByGUID(GUID, Position)
InstanceService.SetEnabled(Name, Boolean, Index)
InstanceService.IsEnabled(Name, Index)
InstanceService.require(Name, Index)
InstanceService.requireByGUID(GUID)

    NetworkService¶

    NetworkService is a service that controls the NetworkEvent Instance to enable two-way communication between ServerScript and ClientScript.

    Note:

    • Name is the name of the NetworkEvent (string); it must match on both the Server and the Client sides for them to receive each other's messages.
    • Index is used when multiple NetworkEvents share the same name, similar to InstanceService's mechanism (if omitted, it defaults to Index = 1). You can use a GUID instead of Name+Index.
    • Username in the Server-side functions is the name of the player to receive the event; pass "*" to send to all connected Clients.
    • FireServer/OnClientEvent can only be called from within a ClientScript, and FireClient/FireAllClients/OnServerEvent can only be called from within a ServerScript. Calling them from the wrong side raises an error.
    • ... is a variable list of parameters (must be serializable: string, number, boolean, plain data table) that is passed intact to the Callback on the receiving side.
    -- Callable from both sides (Server/Client), used to create/destroy the NetworkEvent Instance
NetworkService.Create(Name, Parent)
NetworkService.Destroy(Name, Index)

-- Only callable within a ServerScript
NetworkService.FireClient(Name, Username, ..., Index)
NetworkService.FireAllClients(Name, ..., Index)
NetworkService.OnServerEvent(Name, Callback, Index)

-- Only callable within a ClientScript
NetworkService.FireServer(Name, ..., Index)
NetworkService.OnClientEvent(Name, Callback, Index)

-- Callable from both sides
NetworkService.Disconnect(Name, Index)

    NetworkEvent¶

    NetworkEvent is an instance used to set up a two-way communication channel between the Client and the Server (similar to RemoteEvent/RemoteFunction in Roblox).

    Note: A NetworkEvent must be placed inside a ServerScript or ModuleScript. It cannot be declared freely outside of a script context.

    How to set up:

    • Create: New -> NetworkEvent, then give the event a unique identifier name.
    • Server listens: use NetworkEvent:OnServerEvent(Callback)
    • Client sends to Server: use NetworkEvent:FireServer(...)
    • Server sends to Client: use NetworkEvent:FireClient(Username, ...) or NetworkEvent:FireAllClients(...)
    • Client listens: use NetworkEvent:OnClientEvent(Callback)

    Note:

    • EventName is the name of the NetworkEvent (string, must be unique across the game).
    • Data passed through a NetworkEvent must be serializable (string, number, boolean, table — functions or userdata cannot be passed).
    • Payload size limit: up to 64KB per call.
    • Avoid calling FireAllClients more than 20 times per second to prevent network congestion.

    ServerScript¶

    ServerScript is an instance containing Luau code that runs entirely on the server; it is never sent to or executed on the client side.

    Note: ServerScript can only access server-side Services. You cannot call client-only APIs (e.g.: CameraService, InputService) directly inside a ServerScript — you must go through a NetworkEvent.

    How to set up:

    • Create: New -> ServerScript, then write Luau code inside it.
    • ServerScript runs automatically when the game starts (server-side).
    • You can require() ModuleScripts to reuse logic.

    Note:

    • ServerScript has access to all server services (DataStoreService, PlayerService, BanService, ...).
    • Variables and state inside a ServerScript are shared among all connected players.
    • A script that hits a runtime error stops executing but does not crash the server; the error is written to the Server Log.

    ModuleScript¶

    ModuleScript is an instance containing Luau code that can be require()-ed from any ServerScript or ClientScript to reuse shared logic.

    Note: A ModuleScript only runs once — its return value is cached. The next require() call receives the same value without running the code again.

    How to set up:

    • Create: New -> ModuleScript, then return a table or value at the end of the script.
    • Use require(ModuleName) in a ServerScript or ClientScript to load the module.
    -- Example ModuleScript named "MathUtils"
local MathUtils = {}

function MathUtils.Add(a, b)
    return a + b
end

return MathUtils

-- Use in a ServerScript or ClientScript:
local MathUtils = require("MathUtils")
local result = MathUtils.Add(3, 5) -- 8

    Note:

    • A ModuleScript can require() other ModuleScripts (circular dependencies are not allowed).
    • If a ModuleScript is require()-ed from both the Server and the Client, it runs separately in each environment — state is not shared.
    • The ModuleScript name must be unique within the game.

    ClientScript¶

    ClientScript is an instance containing Luau code that runs entirely on each player's machine (client-side); it has no access to server services.

    Note: A ClientScript cannot access DataStoreService, BanService or any server-only API. To interact with the server, you must use a NetworkEvent.

    How to set up:

    • Create: New -> ClientScript, then write Luau code inside it.
    • ClientScript runs automatically on every client when a player joins the game.
    • You can require() ModuleScripts to reuse logic.

    Note:

    • ClientScript has access to client services (CameraService, UIService, InputService, EffectService, ...).
    • Each player has their own ClientScript instance — state is not shared between clients.
    • A script error on a client only affects that client; it does not affect the server or other clients.

    NetworkEventService¶

    NetworkEventService is the service that manages all NetworkEvents in the game, letting you register, send and listen to network events between Client and Server using Luau code.

    Note:

    • EventName is the name of a NetworkEvent created in the Explorer (string, must be unique).
    • Username is the name of the player to receive the event (string); pass "*" to send to all clients.
    • ... are arbitrary data parameters that must be serializable (string, number, boolean, table).
    • Callback is the function that processes data received from the event.
    • When calling from a ServerScript: use FireClient, FireAllClients, OnServerEvent.
    • When calling from a ClientScript: use FireServer, OnClientEvent.
    -- ===== SERVER SIDE (ServerScript) =====

-- Listen for events sent up by clients
NetworkEventService.OnServerEvent(EventName, function(Username, ...)
    -- process data from the client
end)

-- Send an event down to a specific client
NetworkEventService.FireClient(EventName, Username, ...)

-- Send an event down to all clients
NetworkEventService.FireAllClients(EventName, ...)

-- Send an event down to all clients except one
NetworkEventService.FireAllClientsExcept(EventName, ExcludeUsername, ...)


-- ===== CLIENT SIDE (ClientScript) =====

-- Listen for events sent down by the server
NetworkEventService.OnClientEvent(EventName, function(...)
    -- process data from the server
end)

-- Send an event up to the server
NetworkEventService.FireServer(EventName, ...)

-- Call the server and wait for a result (invoke)
NetworkEventService.InvokeServer(EventName, ...)

-- Listen for client invokes (the server processes and returns a result)
NetworkEventService.OnServerInvoke(EventName, function(Username, ...)
    return result
end)


-- ===== SHARED =====

-- Stop listening to an event
NetworkEventService.Disconnect(EventName)

-- Check whether an event exists
NetworkEventService.Exists(EventName)
