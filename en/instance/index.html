    Noobietoria Studio — Instance Reference¶

    List of the Instances available in Noobietoria Studio, along with the related services used to control them.

    Part¶

    Part is a basic object in Noobietoria Places.

    Properties: RGBA, Image Texture (NImageAssets), Size (XYZ), position and orientation.

    Types: Part(Block), Sphere, Wedge, Cylinder, MeshPart, Triangle, Mesh.

    Related services: TweenService, InstanceService, CollisionService, PhysicsService

    TrussPart¶

    Child of Part. TrussPart is an object that lets you climb.

    Properties: Includes all Part properties plus ClimbSpeed.

    Related services: Same as Part.

    Attachment¶

    Attachment is an anchor point in the 3D environment.

    Properties: Position, Orientation.

    Related service: InstanceService

    Folder¶

    Folder is a pure container used to group and organize other Instances in the hierarchy. Folder has no physics or rendering properties — it is just a logical "folder".

    Properties: Name, Parent.

    When to use: Use it to gather Instances of the same type or purpose for easier management (for example: grouping all NetworkEvents into a Folder named Events, or grouping configs into Settings).

    Related services: InstanceService

    Model¶

    Model is a container used to group Parts and 3D objects into a single unit; you can set a PrimaryPart to position and move the entire group at once.

    Properties: Name, Parent, PrimaryPart (the Part chosen as the Model's coordinate origin).

    When to use: Use it when you need to group multiple Parts into one complete object (characters, vehicles, buildings, props...). Moving/rotating the Model applies to all Parts inside it via the PrimaryPart.

    Note

    Always set PrimaryPart before using InstanceService.SetPivot or InstanceService.MoveTo on a Model, otherwise a runtime error will occur.

    Related services: InstanceService, TweenService, PhysicsService

    Frame¶

    Frame is an object containing everything related to GUI.

    Properties: RGBA, Size (XY), position and orientation.

    Related services: InstanceService

    TextLabel¶

    TextLabel is an object that displays text.

    Properties: RGBA, Size (XY), position and orientation, Text (text content), TextSize, Font, TextColor3.

    Related services: InstanceService, TextService

    TextButton¶

    TextButton is an object that acts as a button.

    Properties: RGBA, Size (XY), position and orientation, Text (text content), TextSize, Font, TextColor3.

    Related services: InstanceService, TextService

    ImageLabel¶

    ImageLabel is an object that displays an image.

    Properties: RGBA, Size (XY), position and orientation, Image (Asset ID from NImageAssets), ImageColor3, ImageTransparency, ScaleType.

    Related services: InstanceService, UIService, TextService

    ImageButton¶

    ImageButton is an object that is a button displaying an image instead of text.

    Properties: Includes all ImageLabel properties plus Text (text drawn on top of the button, can be left empty).

    Related services: InstanceService, UIService, TextService

    TextBox¶

    TextBox is an object that lets players type text.

    Properties: RGBA, Size (XY), position and orientation, Text, PlaceholderText, TextSize, Font, TextColor3, ClearTextOnFocus, MultiLine.

    Related services: InstanceService, UIService, TextService

    ScrollingFrame¶

    ScrollingFrame is a Frame that can be scrolled when the content inside exceeds the frame size.

    Properties: Includes all Frame properties plus CanvasSize (XY), ScrollBarThickness, ScrollingEnabled, ElasticBehavior.

    Related services: InstanceService, UIService

    NetworkEvent¶

    NetworkEvent is an object used for networking (two-way communication) between ServerScript and ClientScript.

    Properties: Name (identifier name, used by both sides to find each other's event).

    Where to place: Should be placed in ReplicatedStorage (or equivalent) so that both the Client and the Server can see this Instance.

    How it works:

    • The Server can call FireClient / FireAllClients to send data down to the Client, and listen with OnServerEvent to receive data sent up by the Client.
    • The Client can call FireServer to send data up to the Server, and listen with OnClientEvent to receive data sent down by the Server.

    Note

    Data passed through a NetworkEvent must be serializable (string, number, boolean, plain data table). Live Instances cannot be passed directly — use a GUID/Name to reference them instead.

    Related services: NetworkService, InstanceService

    ServerScript¶

    ServerScript is a Script that only runs on the server (Server), does not replicate down to the Client, and the Client cannot read the source code inside it.

    Properties: Source (Luau code), Enabled (enable/disable script execution), Parent.

    How it works: Runs as soon as it is created / when the server starts (depending on where it is placed), with full access to Server-side Services (DataStoreService, BanService, PurchaseServiceIG, ...).

    Note

    Use ServerScript for sensitive logic (economy, anti-cheat, data) because the Client cannot interfere with or view it.

    Related services: NetworkService (to communicate with Clients via NetworkEvent), all Server-side Services.

    ClientScript¶

    ClientScript (also known as LocalScript) is a Script that only runs on each player's Client machine.

    Properties: Source (Luau code), Enabled, Parent.

    How it works: Only runs on the machine of the player who owns it (usually placed in StarterPlayerScripts or equivalent), and does not have direct access to sensitive Server-side Services (DataStoreService, BanService, ...).

    Note

    Use ClientScript for UI, effects, input, camera — things that only affect that player's own experience. To change shared data (currency, inventory, ...) you must send a request via a NetworkEvent up to a ServerScript for processing.

    Related services: NetworkService, InputService, CameraService, UIService, TextService

    ModuleScript¶

    ModuleScript is a Script that can be reused (require-able from other Scripts), used to share common functions/data, and does not run on its own when created.

    Properties: Source (Luau code, must return a value — usually a table), Parent.

    How it works: It is loaded via the require(Instance) function, runs exactly once, and returns (caches) the same value for every subsequent require within the same environment (Server or Client).

    Note

    A ModuleScript placed in a shared area (e.g. ReplicatedStorage) can be required by both the Server and the Client; a ModuleScript placed only on the Server side (e.g. ServerStorage) can only be required by ServerScripts.

    Related services: InstanceService

    Combined example: Client ↔ Server via NetworkEvent + ModuleScript¶

    -- (ModuleScript "EconomyUtils" in ReplicatedStorage)
local EconomyUtils = {}

function EconomyUtils.FormatCoin(amount)
    return "🪙 " .. tostring(amount)
end

return EconomyUtils

    -- (ServerScript, uses InstanceService to require the ModuleScript
--  and NetworkService to listen to the Client)
local EconomyUtils = InstanceService.require("EconomyUtils")

InstanceService.Create("BuyItem", "NetworkEvent", "ReplicatedStorage")
NetworkService.OnServerEvent("BuyItem", function(Username, ItemId)
    CurrencyService.Deduct(Username, "Coin", 100)
    NetworkService.FireClient("BuyItem", Username, "ok", EconomyUtils.FormatCoin(CurrencyService.GetBalance(Username, "Coin")))
end)

    -- (ClientScript)
NetworkService.OnClientEvent("BuyItem", function(status, message)
    if status == "ok" then
        UIService.SetText("CoinLabel", message)
    end
end)

UIService.OnClick("BuyButton", function()
    NetworkService.FireServer("BuyItem", "Sword_01")
end)
